# Trusted Intelligence Runtime — research release candidate
Mission: independently test the relationship between model capability and host-authorized execution. The public application playground is not the core product.

## Trust boundary
An authenticated trusted application host independently selects category and record ID. User intent is not permission. An atomic SQLite admission transaction checks tenant/category/record ACL, rate, replay and a dedicated inference budget before calling a provider. A failed or timed-out attempt consumes the reservation; operators must use a new request ID only after review. The model receives the operation description and supplied intent, never record contents, tenant credentials, authorization tables or secrets. Use synthetic or explicitly approved non-sensitive inputs only; caller intent itself may contain sensitive information and this module does not redact it. The provider must enforce its own timeout and network/data policy. Output must be an exact JSON proposal matching the host task; the existing secure service independently checks record scope, replay and budget when executing a read. No model-granted authority, write actions or public endpoint. Direct legacy read requests are a separate trusted-host interface; production deployment must prevent bypass paths.

## Evidence
Run `python -m unittest -v swapnil_ai_labs.test_trusted_runtime secure_service.test_service`. Run CPU integration using the pinned model and dependency versions in .github/workflows/trusted-runtime.yml. The Qwen model is third-party, not trained or owned by Swapnil AI Labs. Authored synthetic cases are not independent or representative. Measure authorized completion separately from rejected requests and pre-inference denials. Report all failures, not just successes. No claim of novelty or superiority.

## Remaining gates
Independent threat review, external evaluation dataset with provenance and licensing, timeouts and cancellation enforced outside provider, identity federation, retention and quotas across multiple processes, migration and backup/restore for admission tables, external audit anchoring, production observability, cost controls, and a customer pilot with consent. Existing context/memory/routing prototypes remain separate; integrate only after access-scoped retrieval and evaluation. No public inference service or production certification.
