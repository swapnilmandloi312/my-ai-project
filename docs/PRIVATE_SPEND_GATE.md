# Private monetary spend gate
Migration 005 adds a disabled-by-default, zero-cap lifetime USD ledger in integer microdollars (1 USD = 1,000,000 units). Admin-only reservation and settlement functions are SECURITY INVOKER. Reservation takes queue stop and spend-limit row locks, rejects duplicates and requests above remaining capacity, and never authorizes paid work at zero cap. Settlement records actual provider charge with an opaque receipt reference; overrun is recorded and disables the gate. Uncertain provider outcome retains reservation until reconciled; no automatic release. Do not retry a duplicate reservation as a new charge. No direct access or EXECUTE for browser/service/worker roles. No paid adapter is connected. A future adapter must obtain a newly created reservation atomically before a provider call, impose an enforceable provider-side maximum, use a provider idempotency key where supported, reconcile provider receipts, and never automatically retry uncertain charges. The ledger is not a provider billing limit and cannot prevent overbilling after a call. Only an authorized founder-approved administrator may change the cap; no UI to change cap is included. Current cap stays zero. Existing synthetic worker never calls paid services. Disposable CI covers default denial, global stop, capacity, duplicate, settlement, overrun freeze and role isolation. No production charges in tests.
