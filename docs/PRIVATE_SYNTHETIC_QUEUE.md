# Private synthetic queue
Additive migration for the existing private workspace schema, not the historical public preview tables. Starts stopped with zero lifetime attempt budget. All tasks require a current workspace membership, explicit founder approval, unpaused category, available budget, and a worker claim. Delegation means a manually requested synthetic child of a successful same-workspace parent. Worker leases expire after 60 seconds; attempts are reserved under a workspace lock, max three per job. Stopping cancels pending, queued and running jobs and invalidates leases; no external actions are implemented. Events and synthetic result JSON are private and visible through a checked membership RPC. The worker uses psql, with credentials injected by the host via standard PostgreSQL environment configuration. Never use a service key in the browser. Do not run the integration fixture in production. Dedicated worker LOGIN provisioning, TLS, real Auth/browser acceptance, rate limits, retention, hosted process and review remain separate release gates. Test against disposable PostgreSQL first. Do not enable a live worker or claim autonomous AI results based on synthetic execution.
