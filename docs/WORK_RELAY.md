# Work Relay — local functional backend candidate
The cross-department website story now has an independently testable state-machine backend. Finance, HR, IT and support share a request, evidence, review, decision and local resolution contract. Synthetic reference IDs only; evidence presence is checked, not truth or document contents. No AI inference or external execution in this backend yet. The Trusted Intelligence Runtime remains a separate verified read-only research component; integrate it after scoped retrieval and model utility evaluation.

## API
GET /healthz; GET /v1/relay/items/{id}; POST /v1/relay/commands. Command shape: command_id, item_id, action, revision, data. create (requester, revision zero, data.department); attach (requester, data.key and data.reference); submit (requester, empty data); approve/reject (separate reviewer, empty data); resolve (separate operator, empty data). Returned revision is required for subsequent commands. Successful command replay returns the saved result for the same principal and exact payload; changed payload with same command ID is rejected. Failed commands are not reserved; clients may retry corrected commands. The local result is not an external accounting, HR, IT or support action.

Run from root: python -m unittest -v swapnil_ai_labs.test_work_relay swapnil_ai_labs.test_relay_http. WSGI factory swapnil_ai_labs.relay_http:from_env() accepts RELAY_DB, RELAY_AUDIT_KEY (hex random 32+ bytes), RELAY_PRINCIPALS (JSON list id, tenant, token_hash SHA256, role, departments). Provision separate trusted test principals for requester/reviewer/operator. Never use fixture credentials outside tests. HTTP smoke uses loopback only. Do not expose development WSGI server.

## Acceptance and remaining work
Transactional state transitions, role separation, requester ownership, tenant scope, optimistic revision, persistent idempotency, evidence completeness and HMAC chain. Local audit is not externally anchored and cannot detect tail truncation. Replay returns historical metadata; role or department revocation requires a fresh configuration and additional replay authorization review. No rate limiting, OIDC, external audit anchor, verified document provenance, encrypted storage, deletion/retention policy, production TLS or load certification. No public hosting or client data. Production gate requires all of these, independent security review and customer authorization. This release is a functional local prototype, not a production certification.
